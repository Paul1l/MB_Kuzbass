# 1. Executive SEO Summary

**Проект:** mb-kuzbass.ru — ИП Пушкарев К. А., б/у оригинальные запчасти Mercedes-Benz и BMW с японских доноров, авто с японских аукционов, машинокомплекты для авторазборов. Склад и выдача — Барнаул; доставка по России.

**Цель:** не трафик, а цепочка «поисковый спрос → релевантная страница → квалифицированный посетитель → поиск детали → звонок или сообщение → продажа».

## Вывод в одном абзаце

Сайт аккуратно сделан и безопасен, но в нынешнем виде не может стать каналом продаж из поиска. Поисковикам доступна **одна страница с пустым HTML**: всё содержимое появляется только после JavaScript, каталог из 30 реальных позиций спрятан на хеш-адресах, цен, наличия, условий доставки, оплаты и гарантии нет. Основной путь заявки ведёт в Telegram-группу: чтобы написать, клиенту нужно вступить в неё и опубликовать сообщение с телефоном на виду у участников, а на iOS открытие Telegram из формы может блокироваться. Есть инфраструктурные риски, которые нужно закрыть в первую неделю: живой сайт уже отличается от репозитория (H1 и тексты правили вне Git), проксирование через Cloudflare (в РФ такие сайты с июня 2025 года ограничиваются до 16 КБ на ресурс), копия сайта на GitHub Pages, потеря HTTPS-редиректа при следующем деплое.

## Пять главных решений

| # | Решение | Почему | ID |
|---|---|---|---|
| 1 | Заморозить выкладки и синхронизировать production с репозиторием; проверить доступность из российских сетей и при необходимости отключить прокси Cloudflare; отключить GitHub Pages; починить `.htaccess` в исходниках | Живой сайт уже отличается от репозитория — следующий деплой откатит правки; без стабильной инфраструктуры любые SEO-работы бессмысленны | C-06, C-01, C-03, C-04 |
| 2 | Перевести заявки из Telegram-группы в личный канал (аккаунт, бизнес-аккаунт или бот); синхронное открытие мессенджера, WhatsApp с готовым текстом, телефон в шапке, липкая панель на мобильном | Самый короткий путь к росту заявок с текущего трафика; данные клиентов перестанут быть видны участникам группы | C-05, H-07, H-10, H-14 |
| 3 | Перейти на пререндер (SSG) с реальными URL: бренды, категории, товары, служебные страницы | Без этого невозможно ранжирование по категориям, моделям, кодам двигателей и товарам | C-02, H-13 |
| 4 | Собрать реальный Wordstat и построить структуру по подтверждённому спросу и реальному наличию; без дорвеев и гео-страниц без присутствия | Частоты пока **DATA NOT VERIFIED**; структура и тексты — гипотезы | раздел 3–6 |
| 5 | Усилить коммерческие факторы реальными данными владельца: цены или «по запросу», статусы, доставка, оплата, гарантия, возврат, отзывы; настроить аналитику до продажи | Это и ранжирование в Яндексе, и доверие покупателя б/у агрегатов | H-05, H-06, H-08 |

## Что подтверждено, а что нет

| Подтверждено по коду и проверкам | Не подтверждено (DATA NOT VERIFIED) |
|---|---|
| Один индексируемый URL; HTML без контента | Частоты Wordstat, позиции, трафик |
| 30 товаров в 6 категориях, без цен и ID | Данные Вебмастера, GSC, Метрики |
| GitHub Pages включён и публикует `main` | Работает ли сайт через Cloudflare у пользователей из РФ |
| Редиректы есть только в корневом `.htaccess` | Какие ещё файлы production на Спринтхосте отличаются от репозитория |
| CI упадёт на `npm audit` | Карточка в Яндекс Бизнесе, регион сайта |
| Lighthouse (локально): mobile 70, desktop 93, a11y 100/96, SEO 100 | Полевые Core Web Vitals |
| География: только Барнаул, «Кузбасс» — название бренда (ответ владельца) | Города регулярной доставки |
| Production отличается от `main` (скриншот владельца) | Полный перечень отличий production от репозитория |
| Хостинг — Спринтхост; Telegram `mbc_kuzbass` — группа (ответы владельца) | Режим Cloudflare (только DNS или прокси) |

> Оценка Lighthouse SEO = 100 не означает, что SEO в порядке: Lighthouse проверяет базовые теги одной страницы и не оценивает, что контент есть только в JS и что URL всего один.

## Ожидаемый эффект (качественно, без выдуманных цифр)

- **0–30 дней:** устранены риски недоступности и дублей, восстановлен зелёный CI, исправлен путь заявки, настроена аналитика, собран Wordstat. Эффект — больше заявок с текущего трафика и корректные данные для решений.
- **31–60 дней:** индексируемые страницы брендов, категорий, товаров и служебных разделов; переписанные Title/H1 по данным Wordstat; коммерческие факторы. Эффект — первые показы по небрендовым коммерческим запросам (замер — Вебмастер).
- **61–90 дней:** страницы моделей и кодов агрегатов там, где спрос и наличие подтверждены; контент, отвечающий на вопросы совместимости; локальные карточки и отзывы; итерации по данным. Эффект — рост квалифицированных кликов и обращений по длинному хвосту.

Прогноз трафика и заявок в цифрах не даётся: без Wordstat, Вебмастера и Метрики он был бы выдумкой. После получения доступов (см. [20-owner-questions-and-access.md](20-owner-questions-and-access.md)) план KPI можно пересчитать.

## KPI

Основные: квалифицированные обращения из органики (звонки, сообщения, заявки с кодом источника), продажи из органики, конверсия органики. Промежуточные: показы и клики по коммерческим кластерам в Вебмастере, доля небрендовых запросов, число проиндексированных коммерческих страниц, CTR сниппетов, позиции по кластерам в регионе Барнаул и по России для негеозависимых запросов.

## Чего мы сознательно не делаем

- Не создаём сотни гео-страниц для городов без реального присутствия и условий.
- Не генерируем страницы «модель × деталь» без спроса и наличия.
- Не пишем SEO-тексты ради объёма.
- Не размечаем рейтинг 2ГИС как собственный.
- Не придумываем цены, гарантию, сроки доставки, отзывы, адреса и наличие — только со слов владельца.
- Не закупаем ссылки.
