# 8. Рекомендуемая архитектура сайта (фазы 8–9)

Принцип: **страница создаётся только при сочетании спроса, наличия, ценности для бизнеса, уникального контента и понятного интента.** Никаких тысяч автоматически сгенерированных комбинаций.

## Структура URL

```text
/                                         Главная: общий кластер, бренд, VIN-подбор, категории, доверие
├── /mercedes/                            Б/у запчасти Mercedes-Benz (бренд-хаб)
│   └── /mercedes/<кузов>/                УСЛОВНО: w211, w204, w212, w203 … (см. правило ниже)
├── /bmw/                                 Б/у запчасти BMW (бренд-хаб)
│   └── /bmw/<кузов>/                     УСЛОВНО: e60, e39 …
├── /katalog/                             Все категории
│   ├── /katalog/dvigateli/               Контрактные двигатели Mercedes-Benz и BMW
│   │   └── /katalog/dvigateli/<товар>/   Пример: /katalog/dvigateli/mercedes-m272-w211-<id>/
│   ├── /katalog/akpp/
│   ├── /katalog/optika/
│   ├── /katalog/kuzov/
│   ├── /katalog/podveska-tormoza-diski/  (возможно разделение после Wordstat)
│   └── /katalog/salon/                   noindex, follow, пока позиций меньше 3–5
├── /avto-iz-yaponii/                     Авто с японских аукционов под заказ
├── /postavki-dlya-avtorazborov/          Машинокомплекты, распилы, контейнеры (B2B)
├── /dostavka-i-oplata/                   Только реальные условия
├── /garantiya-i-vozvrat/                 Только если гарантия реально есть
├── /o-kompanii/                          История бренда, склад, команда — со слов владельца
├── /kontakty/                            NAP, карта (статичное изображение + ссылки на Яндекс Карты и 2ГИС), режим
├── /otzyvy/                              УСЛОВНО: только при достаточном количестве реальных отзывов с согласием
├── /stati/<slug>/                        УСЛОВНО: при подтверждённом спросе
├── /rekvizity/
└── /dokumenty/<документ>/               Политика, согласие, соглашение, cookie
```

Правила URL: строчные буквы, транслитерация, слэш в конце (единообразно, с 301 для варианта без слэша), без параметров, без дат. ID товара в конце слага защищает от коллизий одинаковых названий.

### Когда создаётся страница модели или кузова

Все условия одновременно:
1. Wordstat подтверждает отдельный спрос по модели (например, «запчасти w211», «разборка w211»).
2. В наличии не меньше 5 позиций этой модели **или** модель регулярно приходит донором.
3. На странице есть уникальное содержание: какие узлы снимаются с доноров, совместимость (рестайлинг или дорестайлинг, двигатели), реальные фото.
4. Есть кому поддерживать актуальность.

Иначе запросы по модели обслуживают бренд-страница и страницы товаров.

### Когда создаётся страница «бренд × категория» (`/mercedes/dvigateli/`)

Только если выдача по запросу «контрактный двигатель мерседес» отличается от выдачи по «контрактный двигатель» (отдельный кластер) и в наличии несколько позиций этого бренда. До этого — фильтр по бренду на странице категории, который **не создаёт отдельный индексируемый URL** (см. фасеты).

## Техническая основа: SSG

Хостинг статический (Apache), поэтому оптимален пререндер при сборке.

| Вариант | Как | Плюсы | Минусы |
|---|---|---|---|
| **A. Пререндер текущего React (рекомендуется)** | React Router: `BrowserRouter` на клиенте и `StaticRouter` на сервере; сборка Vite client + SSR entry; скрипт обходит список маршрутов (из `catalog-products.json` и статических страниц), вызывает `renderToString`, пишет `dist/<маршрут>/index.html` с собственными Title, Description, canonical, OG и JSON-LD; на клиенте `hydrateRoot` | Переиспользует существующие компоненты и стили; малый объём переписывания; хостинг не меняется | Нужно аккуратно убрать обращения к `window` при рендере (параллакс, cookie) |
| B. Astro | Статические страницы с «островками» React (карусель, cookie, форма) | Минимум JS по умолчанию, коллекции контента, лучшая скорость | Больше переписывания |
| C. Next.js (static export) | — | Популярен | Тяжелее, избыточен для этого хостинга |

Требования к реализации (критерии приёмки — в [17-development-tasks.md](17-development-tasks.md)):
- HTML каждой страницы содержит H1, основной текст, ссылки и данные товаров **без выполнения JS**;
- несуществующие пути отдают **404** (без soft-404 через оболочку SPA);
- старые хеш-ссылки перенаправляются скриптом на новые пути;
- `sitemap.xml` генерируется из маршрутов;
- Метрика учитывает переходы как обычные просмотры страниц (согласие сохраняется).

## Модель данных товара

Сейчас у товара есть: `title`, `meta`, `description`, `images`. Нужно (заполнять **только реальными данными**, пустые поля не выводить):

| Поле | Обязательно | Пример значения / комментарий |
|---|---|---|
| `id` | Да | Внутренний артикул, неизменный |
| `slug` | Да | `mercedes-m272-w211-0012` |
| `status` | Да | `available` / `reserved` / `sold` / `on_request` |
| `brand` | Да | Mercedes-Benz / BMW |
| `model`, `body` | Да | E-Class, W211 |
| `yearFrom`, `yearTo` или год донора | Желательно | Год донора |
| `category`, `partType` | Да | Двигатель |
| `code` | Если есть | M272 / ZF 6HP26 |
| `oemNumbers[]` | Если есть | Номера с детали — главный источник длинного хвоста |
| `side` | Для оптики, кузова | Левая / правая / комплект |
| `condition` | Да | Описание состояния, дефекты |
| `mileage` | Если известен | Пробег донора (если есть подтверждающий документ) |
| `donor` | Желательно | Модель, год, частичный VIN (без персональных данных) |
| `compatibility[]` | Желательно | Модели и годы, подтверждённые продавцом |
| `price` / `priceNote` | Да | Цена или «по запросу» + причина |
| `location` | Да | Барнаул |
| `images[]` | Да | Реальные фото, несколько ракурсов, маркировки |
| `updatedAt` | Да | Дата проверки наличия |

В CI добавить проверку схемы каталога (JSON Schema), чтобы пустые или противоречивые записи не попадали на сайт.

## Жизненный цикл товара

| Статус | Код ответа | Индексация | Что видит пользователь | Разметка |
|---|---|---|---|---|
| В наличии | 200 | index | Цена или «по запросу», CTA «Уточнить по этой детали» с ID | `Product` + `Offer` (`InStock`, если цена видима), `itemCondition: UsedCondition` |
| Резерв или временно нет | 200 | index | Плашка «В резерве / уточните наличие», похожие позиции, подписка «сообщить» через мессенджер | `OutOfStock` или `availability` не указывать |
| Продано, у страницы есть показы или внешние ссылки | 200 в течение 60–90 дней | index → затем по ситуации | «Продано», похожие позиции этой модели и категории, «Найдём аналог — пришлите VIN» | Без `Offer` |
| Продано, у страницы нет показов и ссылок | 301 на ближайшую категорию или модель | — | — | — |
| Продано, аналогов не бывает (единичная редкость) | 410 | — | — | — |

Правила против soft-404 и тонких страниц:
- страница «продано» без похожих позиций и полезного текста хуже, чем 301;
- массовые 404 после продажи не допускаются: решения принимаются по данным Вебмастера (показы, ссылки);
- в sitemap — только доступные и зарезервированные товары;
- товары без реальных фото и минимального набора полей не публикуются.

## Фильтры и фасеты (на будущее)

Сейчас фильтров нет — ловушек обхода тоже. Когда позиций станет больше 50–100:
- фильтры по бренду, модели, году, статусу работают через параметры (`?brand=bmw`) с `canonical` на страницу без параметров и `Clean-param` в `robots.txt`;
- отдельный индексируемый URL получает только комбинация, которая прошла правила выше (спрос + наличие + уникальность);
- сортировка и пагинация не создают индексируемых дублей (`canonical` на первую страницу или самоканонические страницы пагинации — по выбранной схеме).

## Навигация

- Шапка: Каталог (выпадающий список категорий), Mercedes-Benz, BMW, Авто из Японии, Поставки для разборов, Доставка, Контакты, телефон, мессенджеры.
- Хлебные крошки на всех внутренних страницах: Главная → Каталог → Категория → Товар; Главная → Mercedes-Benz → W211.
- Футер: категории, бренды, служебные страницы, реквизиты.
- Мобильная версия: бургер-меню с крупными пунктами и липкая панель «Позвонить / WhatsApp / Telegram».
