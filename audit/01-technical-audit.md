## B. Сводка текущей системы

MB Kuzbass — статический одностраничный сайт индивидуального предпринимателя (ИП Пушкарев К. А., ИНН 420211367957), который продаёт оригинальные б/у запчасти Mercedes-Benz и BMW с японских автомобилей-доноров, подбирает и привозит автомобили с японских аукционов и поставляет машинокомплекты авторазборам. Точка выдачи и адрес для клиентов — Барнаул, Северо-Западная ул., 4р. Сайт не принимает заказы и оплату: все конверсии уходят в Telegram (основной канал), WhatsApp, VK и на телефон.

**Проверка production 02.10.2026** ([21-production-check-2026-10-02.md](21-production-check-2026-10-02.md)) показала, что живой сайт опережает репозиторий: на нём уже 7 статичных посадочных страниц, новый H1 и Title главной, sitemap из 8 URL. Пункты ниже описывают репозиторий; где production отличается — это отмечено в карточках строкой «Статус на production».

Технически сайт аккуратный и безопасный для своего масштаба: строгий CSP, согласие на cookie, проверки сборки. Но как канал привлечения он почти не работает:
- поисковикам доступен **один URL** с пустым HTML, весь контент появляется только после JavaScript;
- каталог из 30 реальных позиций не индексируется как отдельные страницы;
- нет цен, статусов наличия, условий доставки, оплаты и гарантии;
- формулировки не совпадают с типичным языком поиска запчастей (гипотеза, требует Wordstat);
- основной путь заявки ведёт в Telegram-группу: чтобы написать, нужно вступить в неё и опубликовать сообщение с телефоном на виду у всех участников; на iOS открытие из формы может блокироваться.

Инфраструктурные риски: production расходится с репозиторием (следующая выкладка откатит правки на живом сайте), копия сайта на GitHub Pages, потеря редиректов при следующем деплое, CI упадёт при следующем push.

### M-16. Адрес без слэша перенаправляется через HTTP

| Поле | Значение |
|---|---|
| Критичность | Medium |
| Область | Техническое SEO |
| Описание | `https://mb-kuzbass.ru/zapchasti-mercedes-barnaul` → 301 на `http://…/` → 301 на `https://…/`. Два перехода и временный переход на незащищённый протокол. Причина: TLS завершается на nginx (openresty), а Apache (`mod_dir`) строит адрес со схемой `http`. |
| Доказательства | `curl -I` (раздел 2) |
| Затронутые файлы и компоненты | `.htaccess` |
| Влияние на пользователя и бизнес | Лишний переход для ссылок без слэша; для браузеров с HSTS незаметно, для роботов — цепочка |
| Рекомендуемое решение | В `.htaccess` до `mod_dir`: правило, добавляющее слэш сразу с `https://mb-kuzbass.ru` (для каталогов), или `DirectorySlash Off` + явное правило. Учесть `X-Forwarded-Proto` (как в ветке `claude/focused-gates-ld1ci1`) |
| Ответственный | Senior Backend Engineer |
| Сложность | XS |
| Тестирование | `curl -I` без слэша → один 301 сразу на `https://…/` |
