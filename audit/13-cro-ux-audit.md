# 13. CRO и UX-аудит (фаза 14)

Проверено в Chromium на 1366×800 и 390×844 (локальная копия сборки из `main`; на production тексты hero уже другие — C-06). Скриншоты: [evidence/](evidence/).

## Путь посетителя сейчас

```text
Поиск → главная (баннер cookie 46% экрана) → hero: Telegram / WhatsApp / ВКонтакте / «Оставить заявку»
      → прокрутка ≈ 2500 px до «Частых категорий» → категория (#hash) → карточка без цены и статуса
      → «Уточнить наличие» → Telegram-группа без контекста товара → вступить в группу и писать на виду у всех
      → или форма: имя / контакт / текст → копирование в буфер → window.open(Telegram) → вставить вручную
```

Самые дорогие разрывы: заявки уходят в публичную Telegram-группу, нет телефона на первом экране, каталог глубоко и без входа из шапки, CTA без контекста товара, сценарий «скопируйте и вставьте».

## Целевой путь

```text
Поиск → страница категории или товара (контент в HTML, цена или «по запросу», статус)
      → липкая панель: «Позвонить» | «WhatsApp: Интересует {ID} {название}» | «Telegram»
      → или «Подобрать по VIN» (VIN + деталь + контакт) → мессенджер с готовым текстом и кодом источника
      → менеджер видит деталь и источник → продажа → отметка в таблице лидов
```

## Мобильная версия — чек-лист

- Липкая нижняя панель связи (не перекрывает cookie-полосу и важный контент).
- Телефон кликабелен везде; цели на каждый клик.
- Карточка товара: фото на всю ширину, цена и статус над первой прокруткой, CTA сразу под ними.
- Размер касания ≥ 44 px; шрифт ≥ 16 px в полях ввода (чтобы iOS не увеличивал страницу).
- Проверка на 360, 390, 414, 768 px; iOS Safari и Android Chrome; Яндекс Браузер.

## Как проверять эффект

- До изменений: снять базовую линию в Метрике (доля кликов по контактам, цели) — при условии, что данные собираются (H-08).
- После: сравнение по неделям; учитывать, что Метрика видит только согласившихся.
- A/B-тесты — после роста трафика; до этого — последовательные изменения с журналом дат.
